# voice: ElevenLabs agent session, `inspect_screen` tool, step speech in sync with the ring

- **What changed:** `app/src/voice/VoiceSession.tsx` is no longer a stub. It runs an ElevenLabs agent session (WebRTC, `@elevenlabs/client`) while mounted. New files, all voice-owned: `app/src/voice/voiceAgent.ts` (framework-free adapter), `elevenlabsConnect.ts` (mic check, `getElevenLabsToken`, `Conversation.startSession`), `voice.css`, `voiceAgent.test.ts`, and `voice/` at the repo root (`system-prompt.md`, `setup-agent.mjs`, which creates or updates the agent and its client tool through the ElevenLabs API).
- **Branch/PR:** `feat/voice` → main. `gh` isn't installed on my machine, so open the PR at https://github.com/Tophacks/LaunchPal/pull/new/feat/voice.
- **How the voice stays in step with the ring:**
  - `launchpal:step` → the instruction is sent to the agent at once as `[screen] <status>: <instruction>`; the prompt makes it say the instruction word for word. fe dispatches the event right after `showRing`, so ring and sentence start together.
  - Customer says "Where do I click?" → agent calls client tool `inspect_screen` (no parameters) → `window.launchpal.inspectScreen("Where do I click?")` → returns `{"status","say"}` after the ring is drawn → agent says `say`. A rejection is returned as `status: "error"` with the speakable message.
  - Ring leaves the screen (status `guiding` or `ready`) while its instruction is still being spoken → output is silenced until that sentence ends (5 s cap). If the same step comes back with no new step event, it is spoken again.
  - On connect, whatever instruction is on screen is spoken (covers a step found while the session was connecting, and Talk pressed mid-setup).
  - Panel button "Ask: Where do I click?" during a voice session is spoken too (it fires no step event; voice notices it through the status store).
  - No greeting (`first_message` is empty), so nothing talks over the first step. An activity signal every 20 s plus `turn_timeout: 30` keeps the agent from asking "are you still there?".
- **What works (verified):** 18 unit tests on the adapter against a fake ElevenLabs session (sync rules above, tool result, errors, stop while connecting). The voice files typecheck against `@elevenlabs/client` 1.36.1 with stand-in declarations for the Wasp modules. `node voice/setup-agent.mjs --dry-run` prints valid-looking requests.

- **How to run/test:**
  1. `app/.env.server`: replace `placeholder` in `ELEVENLABS_API_KEY=placeholder` with a real key.
  2. `node voice/setup-agent.mjs` (reads `app/.env.server`) → prints `ELEVENLABS_AGENT_ID=agent_…`; add that line to `app/.env.server`. Re-run the script after editing `voice/system-prompt.md` or the guide; with the agent ID set it updates in place.
  3. `cd app && wasp install && wasp start`, then `cd desktop && npm run fixture-demo`. Press **Talk**, allow the microphone. Expect "Click Connect workspace." as the ring appears; click the fixture and expect the next step; ask "Where do I click?" out loud.
  4. Tests: `cd app && npx vitest run src/voice` (I ran them outside the Wasp tree).
